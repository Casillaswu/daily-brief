日报规则
子总代
按「渠道管理列表」的所属总代分组（媒体 × 包型，例如 A8 · Tiktok · 原生包）；没导入对照表时用总代 + 媒体 + 包型代替
子总代一览
按媒体分组，列出全部子总代。栏位上的日期：单日 = 最新一个数据日；「比 X–Y 日均」= 跟它之前最多 7 个数据日的日均比（不足 7 天时用现有的数据日）；区间 = 最近 7 个数据日；本周消耗 < $3,000 的标「样本小」不判断质量（单日自然波动约 ±20–30%，所以不跟前一天比）。「本周」= 最近 7 个数据日。一句话：本周质量（偏低 / 正常 / 优于同包型）+ 昨天的明显变化（消耗暴增或明显缩量 = 1.5 倍 / 一半；首充ROAS 大幅转好或腰斩 = 1.5 倍 / 一半，昨天消耗 ≥ $500 才判断）。点 ▸ 可展开看底下的渠道。最新一天全站消耗不到前 7 日日均的 60% 时，会提醒可能不是完整一天，并且暂停所有「昨天」的判断
非投放总代
官方、商店包、社媒等不在 TPD / A8 下的总代，只看注册与首充人数（看自然量有没有变化）。首充栏位是改版后新增的，之前上传的日期要重新拖一次原档才会有
问题清单
本周（最近 7 个数据日）消耗 ≥ $3,000，且一级首充ROAS 比「同包型其他花费」低 15% 以上（可比部分不到一半不判断）。按少回收金额排序；标签看最近 4 周：连续偏低标「连续 N 周」，不连续标「近 4 周有 N 周偏低」，没有历史标「历史不足」；缺数据的周显示「—」。没有可比同包型花费的子总代另列「无法判断」
差在哪段
跟同包型其他花费比（对照组按自己的包型比例重新加权）：注册成本、注册转首充、首充客单三段，比别人差 5% 以上的就列出，并对应要找谁、要求什么；某段归零时直接点名
预算分布
子总代里近7日消耗 ≥ $1,000 的渠道，各自跟「自己包型的其他花费」比（跟灯号、加量规则同一条正常线）：低 15% 以上的算「差」，其余算「不偏低」。差渠道占子总代消耗 ≥ 40% 且有不偏低的渠道时，建议在子总代内把预算从差渠道转过去；没有可接的渠道且差渠道占 ≥ 70% 时，建议先降回测试预算
为什么不只是减量
历史回测：被判偏低的子总代减量后，下周仍偏低的约 3/4。减量只是少亏，要改善得处理差的那一段
加量规则
D7 数据接上前：渠道最近 3 个数据日，每天一级首充ROAS 都高于正常线 15% 以上（且每天消耗 ≥ $100），才可加量，单次 ≤ +20%。本周质量判为差、亮红灯、「质量好但在下滑」或在问题卡里被点名为差的渠道不列入；「加量后质量下滑」的黄灯会注明，近 3 日真的回升才写回升
紧急异常
最新一天可能不完整时暂停。最新一天、消耗 ≥ $2,000 的子总代：消耗是前 7 日日均的 1.5 倍以上，或一级首充ROAS 不到前 7 日的一半。日波动本来就有 ±20–30%，没到这个程度不报

      预警规则
      纳入条件
      近7日消耗 ≥ $3,000 且一级首充 ≥ 30 人（小渠道样本太小，不判断）；数据不满 14 个数据日时不给任何灯号
      正常线
      同包型（TPD + A8 合并）里除了这个渠道自己以外的所有渠道，近7日一级首充ROAS（按消耗加权）。排除自己，避免大渠道把标准拉向自己；其他渠道近7日消耗不足 $1,000 时不比较。渠道的包型取近7日花费最多的那个，只拿它在该包型下的表现来比。大盘一起涨跌时正常线也跟着变，不会误伤单一渠道
      质量
      渠道近7日一级首充ROAS 高于正常线 15% 以上 = 优；低于 15% 以上 = 差；其余 = 中
      加减量
      近7日消耗比前7日 +15% 以上 = 加量；−15% 以下 = 减量；其余 = 持平；前7日没有消耗 = 新投
      🔴 红灯
      质量差，却在加量、持平或新投 → 该减量
      🟡 黄灯
      ① 质量差、已在减量 → 追踪首充ROAS 有没有回到正常线（减量后反而再跌 15% 以上 → 考虑停投）；② 质量不差但加量后首充ROAS 比前7日跌 15% 以上 → 加量后质量下滑；③ 质量优但首充ROAS 比前7日跌 15% 以上 → 质量好但在下滑，先别加量
      🟢 绿灯
      质量优且首充ROAS 没有比前7日跌 15% 以上 → 可加量；已在加量且质量维持 → 加量有效
      顶部红条
      任一总代近7日 总ROAS 升 > 5% 且一级首充ROAS 跌 > 3% 时出现：总ROAS 的上升来自复充（现有数据分不出老客与新客的复充），不代表新买进来的量的首充回收
      主因
      一级首充ROAS（近7日 vs 前7日）的变化拆成「注册成本 / 注册转首充 / 首充客单」三段，跌最多的那段就是主因；第二段的跌幅达第一段的 80% 以上时标「混合」。只解释变化，不决定灯号
      媒体 × 总代 判断
      同一总代、同一媒体近7日消耗 ≥ $3,000 才判断。「应有水平」= 按它在各包型的花费比例，套用各包型「其他花费」的一级首充ROAS 加权算出（同样排除自己）；某包型其他花费不足 $1,000 时那部分不比，实际值与差额也只算可比部分，可比部分不到一半就不下判断。主力渠道的状态按它实际的灯号原因描述（亮红灯 / 正在下滑 / 减量追踪中）。差 = 低于应有水平 15% 以上 → 该检讨；花最多的渠道占 ≥ 40% 且亮黄/红灯 → 看起来好但先别加量；优 → 可加量候选
      TPD vs A8
      同媒体 / 同包型两边近7日都 ≥ $3,000 才比较；一级首充ROAS 相差不到 10% 视为打平；有一边首充为 0 时照样比胜负与差额，只是不拆原因。差距拆成注册成本、注册转首充、首充客单三段，列出让赢的一边领先的那几段
      本周建议动作
      减量 = 红灯渠道；考虑停投 = 减量后首充ROAS 反而再跌；冻结 = 加量后下滑或质量好但在下滑；小步加量 = 绿灯；检讨整个媒体 = 媒体判断为差且少回收 ≥ $1,000。都只看一级首充（当期），还没有 D7 留存与复充，执行前请看渠道明细
      回收差额
      近7日消耗 ×（渠道一级首充ROAS − 正常线）。负数 = 同样的钱放在正常线水平的渠道，能多回收这么多一级首充金额。红灯按它排序（差最多的在前）；黄灯中「加量后质量下滑」改用「比加量前效率少回收的金额」（近7日消耗 × 首充ROAS 下降幅度）一起排序；绿灯按质量排序
      2日 / 3日 / 7日
      一级首充ROAS 最近 N 个数据日 vs 再往前 N 个数据日，只作参考，不决定灯号
      为什么不用总ROAS
      总ROAS 含渠道老用户复充，会随时间自然变好看；两者方向相反时，顶部红条会特别标出
      包型
      取渠道名称第一段（原生包 / 轻量包 / H5 / PWA）
      媒体
      优先按「渠道管理列表」：渠道 ID → 所属总代「X_投放_媒体_包体_短名」的媒体段（Tiktok / Facebook / Google / GoogleSearch / DSP / Kwai / Microsoft / 网红）。没导入或新渠道不在表里时，才按渠道名称关键字推断：FB/Facebook → Facebook；GG/GGS/谷歌/SEM → Google；TT/TikTok → TikTok；Kwai → Kwai；Mobflyer、Nativex、Liftoff、Moloco、Unity、PropellerAds、Moboost、Mobupps、Tec-Do、iClick、AD- 开头等 → DSP/网盟；商店包/OPPO → 应用商店；其余 → 未标注（A8 多数渠道名称只有代理代号，会落在这里）

      导入每日报表

      把 CSV（或原始 .xlsx）拖到这里，可一次放多天。也可以拖入后台「渠道管理列表」导出档，用来对照每个渠道的媒体。
      同一天重复上传会覆盖旧数据；渠道新增、减少都会自动重新计算。
